## What you get

<CardGrid>
	<Card title="Typed messages" icon="approve-check">
		A `Bus[T]` carries one message type and handlers are `func(T)`. No reflection, no `interface{}`: a
		handler that doesn't fit is a compile error.
	</Card>
	<Card title="In order, in parallel" icon="list-format">
		Each subscriber has its own queue and goroutine, and handles its messages one at a time, in the order
		they were queued.
	</Card>
	<Card title="Bounded waits" icon="clock">
		When a queue is full, Publish waits for room without holding a lock, and gives up when its context is
		done. The rest of the bus carries on.
	</Card>
	<Card title="Unsubscribe with a handle" icon="close">
		Subscribe returns the func that ends that subscription, and only that one. A handler can call it to
		unsubscribe itself.
	</Card>
	<Card title="Graceful shutdown" icon="approve-check-circle">
		Close waits until every queued message has been handled, or its context is done. A message Publish
		queued is never dropped.
	</Card>
	<Card title="Lean" icon="rocket">
		Publish allocates nothing while there is room, and tests guard the allocation counts. No dependencies
		beyond the standard library.
	</Card>
</CardGrid>

## Coming from v1

<div class="landing-lead">
	The idea is the same: publish to a topic, and every subscriber gets the message. The bus is typed now,
	Subscribe hands back a func to unsubscribe with, and Publish takes a context.
</div>

<div class="compare">

```go title="v1"
bus := messagebus.New(100)

handler := func(e OrderPlaced) {
	sendReceipt(e)
}
bus.Subscribe("orders", handler)
bus.Publish("orders", OrderPlaced{ID: 7})

bus.Unsubscribe("orders", handler)
```

```go title="v2"
bus := messagebus.New[OrderPlaced](100)

unsubscribe, err := bus.Subscribe("orders",
	func(e OrderPlaced) {
		sendReceipt(e)
	},
)
err = bus.Publish(ctx, "orders",
	OrderPlaced{ID: 7})

unsubscribe()
```
